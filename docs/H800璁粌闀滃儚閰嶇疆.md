# H800 训练镜像配置

这台机器是 H800 80GB，驱动 `580.82.07`，面板显示 CUDA `13.0`。为了优先吃满 H800 性能，不建议在平台菜单里选择 TensorFlow `2.9.0`、`2.5.0` 或 `1.15.5`，这些版本太旧，不适合作为 Hopper/H800 的训练主环境。原来的 `docker/Dockerfile` 仍保留 TensorFlow `2.1.0`，用途是复现论文旧 `.h5` 权重和验证官方脚本；真正重新训练时推荐使用 `docker/Dockerfile.h800-ngc`。

H800 训练基础镜像选择：

```text
nvcr.io/nvidia/tensorflow:24.05-tf2-py3
```

这个镜像来自 NVIDIA NGC，属于面向 NVIDIA GPU 优化的 TensorFlow 2 容器，适合 H800 这类 Hopper 卡。Python 3.14 可以作为本仓库脚本兼容性的本地开发解释器，但目前不作为 TensorFlow GPU 训练主环境；原因是训练性能由 TensorFlow CUDA/cuDNN/XLA 后端决定，强行切到 Python 3.14 会牺牲深度学习框架和 GPU 后端兼容性，反而更容易跑不满或跑不起来。

构建 H800 镜像：

```bash
docker build --platform linux/amd64 \
  -f docker/Dockerfile.h800-ngc \
  -t nature613-h800-train:latest .
```

先检查 GPU 和依赖：

```bash
docker run --rm --gpus all --platform linux/amd64 \
  nature613-h800-train:latest \
  python scripts/inspect_environment.py
```

正式训练前只做 dry-run：

```bash
docker run --rm --gpus all --platform linux/amd64 \
  -e NATURE613_ALLOW_TRAINING=1 \
  -v /data/M1_M20_train_val_test_set:/workspace/Data \
  -v /outputs/nature613:/workspace/outputs \
  nature613-h800-train:latest \
  python scripts/train_entrypoint.py \
    --train-script official/AI_model_and_files/train.py \
    --data-dir Data \
    --output-dir outputs \
    --dry-run
```

正式训练命令：

```bash
docker run --rm --gpus all --platform linux/amd64 \
  -e NATURE613_ALLOW_TRAINING=1 \
  -v /data/M1_M20_train_val_test_set:/workspace/Data \
  -v /outputs/nature613:/workspace/outputs \
  nature613-h800-train:latest \
  python scripts/train_entrypoint.py \
    --train-script official/AI_model_and_files/train.py \
    --data-dir Data \
    --output-dir outputs
```

如果要尽量吃满 H800，优先使用单卡 H800 80GB 跑完整 batch，先不要多卡并行，因为官方 `train.py` 没有写分布式策略。H800 显存足够，默认 `batch_size_training = 2048` 应该先保持不降；如果 GPU 利用率长期低于 80%，再考虑把官方 `train.py` 里的 batch size 提高到 `4096` 或 `8192` 做短跑测试。每次只跑前 10 到 20 分钟观察 `nvidia-smi`，重点看 GPU 利用率、显存占用、每 step 时间和是否出现 OOM。

性能优先级建议：

```text
H800 80GB + nature613-h800-train:latest
> RTX PRO 6000 / RTX 4090 + 同一镜像
> 旧 TensorFlow 2.1 兼容镜像
> CPU
```

不要为了 Python 3.14 本身牺牲 TensorFlow GPU 容器。这个项目里 Python 只负责调度数据生成器和 Keras 训练入口，真正决定速度的是 TensorFlow 是否能正确调用 H800 的 CUDA/cuDNN 后端。
